  Layer 3 and 4's MLP are called twice. Each call to self.blocks[i] goes 
  through Block.forward → MLP.forward.                                   
                                                                         
  The bug: when layer 3 runs the second time, the copy_() from the first 
  run already updated self._act_scale. So the second run uses the FIRST  
  run's scale (not the previous step's). That's fine for accuracy. But   
  the copy_() after each MLP call creates a data dependency: the amax    
  kernel must complete, then copy_() must complete, before the next      
  operation. With 17 calls instead of 11, that's 6 extra serialization
  points.

  scaling's amax is part of the autograd function's compiled graph, where

  copy_() is in MLP.forward, creating a separate sync point between
  layers.

  the copy_() for repeated layers since the scale barely changes within
  one step. But we can't easily detect repeated calls inside compile.
